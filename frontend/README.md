# Frontend для SensorBackend

Статичний дашборд (без збірки та залежностей) для даних із `data.db`.
Вміст:

```
frontend/
├── index.html              ← розмітка (дві секції: Температура / Вологість)
├── styles.css              ← стилі (світла/темна тема автоматично)
├── app.js                  ← завантаження даних, гістограми, тижневий зріз
├── api_suggested.go.txt    ← ГОТОВИЙ код ендпойнтів для бекенду (скопіювати)
└── README.md               ← цей файл
```

Розділення сторінки зроблено рівно за твоїм описом, у кожній секції зверху вниз:

1. **Актуальні дані** — по центру найсвіжіше значення + час виміру.
2. **Гістограма за 24 години** — погодинні середні (24 стовпці), наведення показує значення та кількість вимірів.
3. **Середнє за тиждень** — список за днями у форматі `17.10 ср · 19.4 °C` (поруч дрібним — другий показник).

---

## ⚠️ Головне: бекенд зараз НЕ має жодного HTTP-ендпойнта

`main.go` робить `http.ListenAndServe(":3000", nil)`, але в `handler.go` **нічого не зареєстровано**:

```go
// handler.go — зараз весь файл це:
package main
```

Тобто всі запити до `http://localhost:3000/...` повертають `404`.
Фронтенд споживає дані з `data.db`, але **сам до SQLite доступу не має** — потрібні
JSON-ендпойнти на боці Go.

Бекенд я **не чіпав**. Нижче — що саме потрібно додати.

## Що потрібно додати в бекенд

Потрібні 3 ендпойнти (вони вже враховують те, що `humidity` у схемі має тип `TEXT`):

| Метод | Шлях                  | Що повертає                                                      |
|-------|-----------------------|------------------------------------------------------------------|
| GET   | `/api/latest`         | `{ "temp": 19.4, "humid": 84.3, "time": "..." }`                  |
| GET   | `/api/hourly?hours=24`| `[ { "label": "01:00", "start": "...", "temp": 19.4, "humid": 84.3, "count": 120 }, ... ]` |
| GET   | `/api/daily?days=7`   | `[ { "label": "17.10", "start": "...", "temp": 19.0, "humid": 76.0, "count": 2880 }, ... ]` |

`/api/hourly` — середні за кожну годину (для гістограми).
`/api/daily` — середні за кожну добу (для тижневого списку).

**Крок 1.** Скопіювати вміст `api_suggested.go.txt` у `handler.go`.

**Крок 2.** У `main.go` перед `http.ListenAndServe(":3000", nil)` додати:

```go
http.HandleFunc("/api/latest", handleLatest)
http.HandleFunc("/api/hourly", handleHourly)
http.HandleFunc("/api/daily",  handleDaily)

// віддавати сам фронтенд з того ж сервера
http.Handle("/", http.FileServer(http.Dir("./frontend")))
```

Все, `go run .` — і сторінка відкривається на `http://localhost:3000/`.

> Якщо відкривати фронтенд окремо (`python3 -m http.server 8080` з папки `frontend/`),
> то запити йтимуть на `http://localhost:3000` і CORS уже прописано в
> запропонованому коді (`Access-Control-Allow-Origin: *`). За потреби змінити адресу
> можна так — перед підключенням `app.js`:
> ```html
> <script>window.SENSOR_API_BASE = 'http://192.168.0.100:3000';</script>
> ```

### Зауваження щодо БД

* Схема: `sensor_data(temperature REAL, humidity TEXT, time TIMESTAMP PRIMARY KEY)`.
  Через `TEXT` для вологості в SQL використовується `CAST(humidity AS REAL)`.
  Радив би колись зробити міграцію до `humidity REAL`, але це не обов'язково.
* `time` зберігається як `time.Time` у форматі Go (`2006-01-02 15:04:05.999999999-07:00`);
  драйвер `go-sqlite3` коректно читає його назад у `time.Time` (перевірено).
* `AddData` у `db.go` використовує `$1,$2,$3` — для SQLite це ок (named-параметри),
  але якщо колись перейдете на Postgres, нічого міняти не треба.

## Запуск і перевірка

```bash
# 1) бекенд (після кроків вище)
cd /home/daniff/SensorBackend
go run .

# 2) перевірка API
curl -s localhost:3000/api/latest
curl -s "localhost:3000/api/hourly?hours=24"
curl -s "localhost:3000/api/daily?days=7"
```

Або відкрити `http://localhost:3000/` у браузері.

## Демо-режим

Якщо ендпойнтів ще немає, сторінка не падає: вона показує зверху жовтий банер
«Демо-режим» і малює згенеровані (детерміновані) дані. Тобто вигляд можна
оцінити вже зараз:

```bash
cd /home/daniff/SensorBackend/frontend
python3 -m http.server 8080
# відкрити http://localhost:8080
```

Коли API з'явиться — демо-дані автоматично зникнуть.

## Що можна налаштувати в `app.js`

| Константа      | Значення | Опис                                |
|----------------|----------|-------------------------------------|
| `REFRESH_MS`   | `30000`  | автооновлення (збігається з опитуванням датчика) |
| `HOURS`        | `24`     | період гістограми                   |
| `DAYS`         | `7`      | період тижневого зрізу              |
| `API_BASE`     | auto     | адреса API (або `window.SENSOR_API_BASE`) |
